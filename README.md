# tg-proxy-stats

Утилита мониторинга Telegram-прокси на Linux. Она читает `conntrack` и привязывает трафик к входящему IPv4 TCP-порту клиента до перенаправления. Для каждого порта доступны объём трафика в обе стороны, число открытых TCP-соединений, число уникальных IP и история подключений.

Служба `tg-proxy-stats.service` снимает показания раз в минуту и слушает события `conntrack` между снимками, чтобы учитывать короткие соединения. Данные и список портов хранятся в SQLite по пути `/var/lib/tg-proxy-stats/stats.sqlite3`. Срок хранения статистики — 30 дней. Время в отчётах указано по Москве.

Начальный список портов на сервере включает `7000–7020 → 1443` и `8000–8020 → 2443`.

## Параметры

Отчёты и управление портами запускаются через `sudo`. Доступ к базе с IP-адресами ограничен пользователем `root`.

| Параметр | Что делает | Пример |
| --- | --- | --- |
| Без параметров | Сводка по всем портам мониторинга за последние 7 суток | `sudo tg-proxy-stats` |
| `--days N` | Период отчёта от 1 до 30 суток. По умолчанию 7 | `sudo tg-proxy-stats --days 14` |
| `--port PORT` | Отчёт по одному порту с разбивкой по дням и историей IP | `sudo tg-proxy-stats --port 7005 --days 7` |
| `--now` | Свежий снимок открытых TCP-соединений и уникальных IP. Вместе с `--port` показывает адреса и число соединений для каждого | `sudo tg-proxy-stats --now` или `sudo tg-proxy-stats --now --port 7005` |
| `--list-ports` | Список входящих и целевых портов, включая ожидающие первого снимка | `sudo tg-proxy-stats --list-ports` |
| `--add-port PORT:TARGET` | Добавить входящий порт и указать целевой порт перенаправления | `sudo tg-proxy-stats --add-port 7021:1443` |
| `--remove-port PORT` | Остановить сбор по порту и убрать его из сводки | `sudo tg-proxy-stats --remove-port 7021` |
| `--collect` | Служебный режим сбора. Эту команду запускает `systemd` | `sudo /usr/bin/python3 -I -u /usr/local/bin/tg-proxy-stats --collect` |
| `-h`, `--help` | Справка по пользовательским параметрам | `tg-proxy-stats -h` или `tg-proxy-stats --help` |

Режимы `--now`, `--list-ports`, `--add-port`, `--remove-port` и `--collect` взаимоисключающие. `--port` можно использовать в отчёте и со свежим снимком. `--days` задаёт период только для отчёта.

## Управление портами

В записи `7021:1443` первый порт указан в ссылке Telegram, а второй — в правиле перенаправления `iptables`. Перенаправление настраивается отдельно. Сбор по новому порту начинается с ближайшего минутного снимка. Изменения списка применяются без перезапуска службы.

Чтобы сменить целевой порт, сначала удалите запись, затем добавьте её с новой целью. Если по удалённому порту уже собиралась статистика, её можно открыть через `--port` до истечения срока хранения.

```bash
sudo tg-proxy-stats --remove-port 7021
sudo tg-proxy-stats --port 7021 --days 30
```

## Как читать отчёт

- **Объём трафика, TCP и IP в сводке** относятся к периоду `--days`. TCP — число соединений, которые сборщик впервые зарегистрировал как установленные за период.
- **IP за период и IP за 15 мин** — уникальные адреса, набравшие от 1 КиБ суммарного трафика в обе стороны по установленным TCP-соединениям за соответствующее окно. Детальная история по `--port` показывает все IP с установленными соединениями, включая малый трафик.
- **TCP и IP в `--now`** — открытые соединения в состоянии `ESTABLISHED` и уникальные адреса среди них на момент запроса. Одно устройство может открыть несколько соединений.
- **«Проверить»** — три и более IP с открытыми соединениями и трафиком от 1 КиБ на адрес в каждом из 15 последовательных минутных снимков. Это повод проверить использование ссылки.

Во всех подробных списках IPv4-адреса отсортированы по возрастанию числового значения. Например, `192.0.2.2` идёт перед `192.0.2.10`.

## Состояние службы

Сборщик запускается командой `sudo systemctl start tg-proxy-stats.service`. Состояние и последние записи журнала можно посмотреть следующими командами.

```bash
systemctl status tg-proxy-stats.service
sudo journalctl -u tg-proxy-stats.service -n 30 --no-pager
```
